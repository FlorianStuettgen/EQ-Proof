```bash
python -m venv .venv

```

## Repository proof

```bash
python scripts/check_repository.py
```

This runs the full test suite with branch coverage, compiles package modules, validates browser JavaScript, regenerates the numerical proof evidence and Control Room demo, checks the three showcase cases, and—inside a Git checkout—requires a clean diff. Run it after committing intentional source and evidence changes.

The complete visitor-workflow and packaging checks are:

```bash
npm ci
npm run test:browser-engine
npx playwright install chromium
npm run test:ui
python -m pip wheel . --no-deps -w dist
python scripts/check_wheel.py
```

The wheel smoke check serves assets from the extracted wheel, so editable installs cannot conceal missing sample files. CI runs it on each supported Python version.

On managed Windows machines, an npm `UNABLE_TO_VERIFY_LEAF_SIGNATURE` error can mean the organization's trusted certificate is in the Windows certificate store. With Node.js 24, this checkout was installed successfully using `$env:NODE_OPTIONS = "--use-system-ca"` before `npm ci`. Certificate verification remains enabled.

## Change discipline

- Any proof-format change requires a schema and compatibility decision.
- Any numerical-repair algorithm change requires a new algorithm identifier or evidence that replay semantics are unchanged.
- Any Control Room semantic change requires a new `CONTROL_ROOM_SCHEMA` version and updates to `docs/SEMANTIC_MODEL.md`.
- Any supported equation-grammar change requires adversarial compiler tests.
- Any adapter change requires source-manifest and malformed-input tests.
- Any README numerical claim must be generated or directly traceable to checked-in evidence.
- The browser, CLI, demo payload, wiki and documentation must use the same terms for reported, detail-reconstructed and risk-adjusted states.
- Coverage must remain at or above the configured gate; the percentage is not a substitute for adversarial tests.

## Deterministic evidence

The repository contains two separately versioned evidence families:

1. lower numerical-repair proof artifacts generated by `scripts/regenerate_evidence.py`;
2. Control Room payloads generated by `scripts/regenerate_control_room_demo.py` and `scripts/regenerate_showcase_cases.py`.

The showcase generator's `--check` option regenerates in memory and compares all committed artifacts without rewriting them. Omit `--check` only when intentionally updating the examples. The cases' CSV, XER and JSON input bytes are canonical LF text on every platform through `.gitattributes`; hashes are still calculated from actual source bytes.

A product release does not automatically change the lower proof algorithm or artifact contract. Regenerate and commit only the evidence whose contract or engine output intentionally changed.

## Release checklist

1. Update package version, changelog and citation metadata.
2. Review whether proof, specification or Control Room schema versions need independent changes.
3. Run `python scripts/check_repository.py`.
4. Inspect deterministic evidence diffs for intentional semantic changes only.
5. Confirm README, semantic model, demo playbook, screenshot and wiki use the same vocabulary.
6. Build a wheel with `python -m pip wheel . --no-deps -w dist`.
7. Open a pull request and require the Python matrix, reproducible evidence scenario and security analysis to pass.
8. Tag only after the main-branch checks pass.
